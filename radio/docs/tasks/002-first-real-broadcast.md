# Task 002 — 第一条真实宇宙广播

## 目标

在已完成的 Next.js 内容管理后台上，接通 DeepSeek 稿件生成与硅基流动 CosyVoice2 语音合成，做出第一条真正可以收听、保存、刷新后重听的节目。重点是内容质量与可运行的最小链路，不做完整收音机或自动节目工厂。

## 当前基线与执行规则

- 仓库：mayloveless/esp32，基线提交 a2bd48ec7b4ec2848c6f44139d41d508c926e040（feat: radio task2）。开始前读取最新代码、项目规则和未提交改动，不覆盖用户的新修改。
- 复用 radio/ 的 Next.js + TypeScript + pnpm、program/service.ts、program/validation.ts、program/types.ts、lib/supabase-server.ts 和现有管理 API/UI。
- Supabase 项目 lhiojnqooreavzmkrzji，表 public.radio_programs，私有 bucket radio-audio。迁移 20260909083603 已应用，不重复执行、不重建、不修改其他业务表。
- 只使用一个文本供应商和一个 TTS 供应商，不引入通用 Agent 框架、复杂 ORM、Redis、独立队列服务、微服务或新仓库。
- 不修改 drum/、drum-web/ 或 ESP32 固件。Web 只是管理后台，不再进行视觉改版。
- 严格按下述检查点执行，每个检查点完成后报告并暂停，等待用户 review。不得一次性执行全部阶段，不得自行批量调用付费 API。

## 检查点 A：补齐现有服务的可靠性与本地保护

先处理以下已发现的问题，不重构整个项目：

1. 目前 assertLocalDevelopmentRequest 只检查 request.url 的 hostname，不能单凭 Host/URL 声称请求来自本机。开发服务器明确绑定 loopback，并对管理及付费写接口做同源/Origin/Fetch Metadata 等适当校验；如确需跨设备访问，另行设计受保护的方式，不能靠伪造 localhost。生产环境继续默认拒绝管理/生成接口，未经用户确认不公开部署或添加账号系统。给出可验证的拒绝测试。
2. program/service.ts 中删除会先删音频再删数据库；替换音频时对旧对象清理结果也没有完整处理。调整为失败可恢复的资源生命周期，避免数据库仍指向已删除文件，避免新文件上传成功但数据库更新失败时留下孤儿。可使用先更新/删除记录再清理对象、补偿或可重试清理等简单方案，记录失败，不要求分布式事务或新队列。
3. 增加必要的输入大小与格式约束，保持服务端密钥隔离。不要让任意客户端写入敏感的 audio_path，也不要允许普通生成流程随意覆盖已完成节目。
4. 现有试听 URL 只有 60 秒有效期。根据音频播放/Range 请求实际需要选择合理有效期并支持过期后重新获取，不将签名 URL 持久化。

完成后运行 lint、typecheck、build 和有针对性的本地测试。此检查点不调用 AI，不改数据库结构，暂停等待 review。

## 检查点 B：真实文本生成与稿件预览

### 供应商

- 文本：DeepSeek，使用用户已配置且实际可调用的模型，当前 OPENAI_TEXT_MODEL=deepseek-v4-flash。模型 ID、baseURL 和 API 参数以用户账户可用信息及当前官方文档为准，不擅自替换成别的模型。
- 新增/整理服务端 DEEPSEEK_API_KEY、DEEPSEEK_BASE_URL、DEEPSEEK_TEXT_MODEL 等配置。可兼容已有 OPENAI_TEXT_MODEL 变量，但明确文档化优先级，不把 DeepSeek 密钥发给 OpenAI，也不将供应商密钥放入 NEXT_PUBLIC_。实际使用的模型与供应商保存在节目配方/元数据中。
- 使用官方或兼容 SDK 的最小调用，不为尚未接入的供应商建立复杂插件系统。优先读取 DeepSeek 官方 API 文档：https://api-docs.deepseek.com/。

### 内容要求

- 表单增加可选主题，保留节目形式、语言、风格；第一版默认中文，新闻和聊天均可生成。主题可由用户填写，也可选择随机生成，不能只有固定的几个宇宙模板。
- 默认生成明确标记为虚构的宇宙广播；没有检索/可信素材时，不将模型编造的现实事件冒充真实新闻。若用户提供真实素材，须保留来源信息及事实/虚构边界。暂不接实时新闻搜索。
- 先让模型生成有意义的语义稿件。新闻应有具体事件、背景与值得听的细节；聊天应有不同说话者的真实推进，而非重复同一句观点。避免空洞文案、套话、无意义随机名词。内容允许荒诞，但必须可理解。
- 返回经过运行时校验的结构化内容，至少包含标题、节目形式、语言、可播报的有序 segments（speaker/text）和必要的来源/虚构标记。可在现有 JSONB 中保存，不新增世界观表、角色表或复杂 schema。区分语义稿件与后续音频/字幕资源。
- 限制用户输入、模型输出长度、超时及并发。初次文本测试只生成一条短节目，约 30–90 秒可播报内容，不为了填满时长而注水。
- 生成稿件后保存在 radio_programs，允许用户查看、修改或放弃稿件。不要将未合成音频的节目标记 ready；保留 queued/generating/ready/failed 的合法状态语义。
- UI 只增加必要的生成、进度、稿件预览/编辑与“合成语音”入口。不自动触发 TTS，不做新 UI 风格。

先完成不需密钥的校验/错误测试，再经用户确认执行一次真实文本生成。报告真实输出摘要、模型、耗时、是否符合结构与内容要求、实际测试结果，然后暂停。不能用 mock 冒充真实生成。

## 检查点 C：硅基流动 TTS 与完整试听

### 供应商与配置

- TTS 使用硅基流动，优先模型 FunAudioLLM/CosyVoice2-0.5B；不使用 OpenAI TTS 或阿里云百炼，不新增其他服务商账号。
- 环境变量：SILICONFLOW_API_KEY、SILICONFLOW_BASE_URL、SILICONFLOW_TTS_MODEL、SILICONFLOW_TTS_VOICE。建议 baseURL 为 https://api.siliconflow.cn/v1，模型实际 ID 与音色必须以官方当前文档和账户可用性确认。
- 文档入口：https://docs.siliconflow.cn/docs/userguide/capabilities/text-to-speech 。实施前确认实际请求字段、内置音色 ID、文本长度限制、输出格式、计费方式和错误响应。不要把之前对价格或音色的口头描述当成已验证的 API 规范。
- 使用内置中文音色，不做声音克隆、训练、实时流式播放或多供应商框架。密钥仅服务端读取，不能提交。

### 音频生成

- 从已保存的语义稿件读取并合成；先实现单人新闻，聊天可以按 speaker 逐段合成并拼接，但不要求本阶段做复杂混音、外星语、音效或音乐。
- 选定一个实际受支持的输出格式，优先 MP3；核对文件 MIME、扩展名、时长、采样率与后续 ESP32 解码的可行性，不虚构硬件已验证。
- 如需分段，按自然句段切分，不截断句子。合并时保证顺序与音频有效性，避免用原始二进制直接拼接不兼容的容器。保留 speaker、文字与音频片段对应关系。
- 使用实际音频时长生成整段或句段级字幕；拿不到精确时间信息时诚实保留粗粒度/待对齐信息，不伪造逐字时间戳。
- 上传到现有私有 bucket，通过数据库保存对象路径、duration_ms 和实际稿件内容。只有音频资源可读取且记录写入成功后才转 ready；失败记录 failed 和可诊断信息，保留已生成的稿件供重试，不重复付费生成文本。
- 前端提供明确的“合成语音”操作、状态、错误、试听、稿件与历史记录；刷新页面后仍能选择已保存节目重新获取有效试听 URL。长耗时应有明确超时、失败与恢复方式，不依赖无限 HTTP 请求或 Vercel 后台常驻进程。
- 用户明确点击才调用付费 TTS。限制单次字符数、并发及最多重试次数，避免自动重试产生不可控费用。默认不批量生成、不无限循环、不在页面加载时自动调用付费 API。

完成前先用测试替身验证失败分支，再在用户确认后执行一次真实 TTS。报告实际模型/音色、文本长度、输出音频格式/时长、保存与重听测试结果，提供生成节目的可查看位置。不要在用户未确认前继续批量合成。
